### September 19 managed AI planner extension (0.8.0)

The owner selected developer-funded AI for task creation, small plans, and saved deadline questions. Calendar → **AI planner** opens directly into planning with **Create a task**, **Plan my work**, and **What’s due?** starters. Users sign in with a Munka account when a service is configured; the managed app exposes no provider/model chooser or API-key fields. It says **No API key needed**, without naming the model, and shows a labeled percentage bar for the daily allowance rather than numeric prompt counts. Quick capture and Guided task remain available offline.

The internal service contract fixes GPT-5.6 Luna (`gpt-5.6-luna`), low reasoning effort, at most five proposed tasks, and **three sent prompts per account per day**. Each follow-up uses an allowance reservation. The server resets the allowance at 00:00 UTC and the app shows that reset in local time; restart, sign-out, changing the PC clock, and a second PC do not refresh it. Failed, cancelled, or invalid-output attempts count after reservation, with no automatic retry. Malformed requests rejected before reservation do not count. The user-facing allowance moves through 100%, approximately 67%, approximately 33%, and empty; it is not a currency balance. A proposal from the final allowed prompt remains editable and saveable after Send becomes unavailable.

**What’s due?** reads saved tasks locally, for free and without a hosted request. It shows the next seven days plus overdue work, excludes Done tasks and archived courses, names its saved-Munka-task source, reports undated work, and never supplies a time for a date-only deadline. Natural-language deadline questions use a prompt to select today, overdue, next seven days, or all dated work; the app then computes the facts locally. Results display at most 40 matches with a full-list indication. This feature does not read external calendars, imported events, files, or syllabuses.

Hosted model input is limited to the conversation, optional selected course name, and local date/time zone. AI sign-in stores a separate Windows-encrypted session and does not upload planner data or enable synchronization. The server owns the provider key; neither the installer nor the user supplies one. The model receives no tools or permission to act on records, files, application settings, or the operating system. Structured output passes server and desktop validation. A separate explicit **Add N tasks** confirmation uses an account-bound, 15-minute local review ticket, revalidates edits and duplicates against current data, and appends the selected tasks atomically. Repeated successful confirmation is idempotent. New requests, cancellation, account changes, expiry, and restart invalidate pending authority. AI task provenance continues to bypass automation rules.

No hosting provider or cloud database has been chosen, and no server, provider key, or live deployment is configured. The supplied Node server uses SQLite for accounts, expiring sessions, and usage counts; passwords are stored as salted scrypt hashes. Planner records remain local unless the separate optional sync feature is explicitly used. The app explains that AI is not connected and keeps local deadlines available; an unknown allowance shows a dash with an unavailable explanation rather than an invented percentage. Technical setup and acceptance are recorded in `outputs/Managed-AI-0.8.0-Setup.md`; a hosted HTTPS origin, server secret, persistent usage database, and provisioned beta accounts are still required. The retained local/personal-provider implementation is available only to unpackaged legacy source testing; it is superseded as the managed app's user flow. These capability restrictions are not a claim of perfect model behavior or a comprehensive security audit.

The parent reports a full 71-test pass and passing managed/legacy native AI suites with disposable profiles and synthetic replies, including refreshed managed validation after the final UI change. The evidence exercises real renderer/IPC, Windows-encrypted sessions, no implicit sync, local deadline truth, clarification, final-allowance review/save, edits/selections, reopening, light/dark, smaller windows, and unavailable service handling. Live connectivity, model quality, and latency remain unmeasured. The original complete eight-capture finish review returned **ship**, with no material fixes. A follow-up opened four updated captures and returned **ship** for the model-free copy and percentage-bar changes; it is not a second full-surface review. See `.impeccable/review/managed-ai-0.8/finish-review.md`. `DESIGN.md` and `.impeccable/design.json` remain unchanged for this ordinary extension. The detector is unavailable because its context-engine binary could not load.

### Historical: September 14 AI planner extension (0.7.0)

Optional **AI planner** replaces the 0.6.0 one-task chat preview with bounded task plans. Describe a goal, receive fixed app-written clarification when needed, review numbered editable tasks, deselect unwanted steps, and explicitly choose **Add N tasks**. Plans contain 1–8 tasks (default maximum 5), with title, due date/time, type, and notes. This creates task deadlines and checklists; it does not book study events. Quick capture and Guided task remain available offline, and Full calendar, Day, Week, Agenda, saved view preferences, imports, and desktop overlays retain their existing workflows.

AI settings offer Ollama locally with no key, Gemini 2.5 Flash-Lite with eligible-account free-tier and data-use disclosure, or the paid OpenAI GPT-5.4 nano API. Ollama uses only `127.0.0.1:11434` and a locally pulled model; cloud providers use Windows-encrypted keys separately from planner data. Switching providers requires an appropriate setup and never silently reuses credentials or sends a conversation to a fallback provider. Explicit consent names the provider and shared conversation, selected course name, and local date/time zone. Balanced/Fast response styles and daily request/task limits are visible. Failed and cancelled requests count toward the per-PC allowance; it is not a dollar spending cap. Provider pricing, Ollama setup and policy details are dated in `outputs/AI-Planner-0.7.0-Security-and-Setup.md`.

The model receives no tools, files, general planner access, or permission to modify records or settings. Structured output is validated and displayed as escaped text; a separate main-process confirmation appends selected validated tasks atomically using a short-lived local review ticket. Duplicate checks, cancellation, and expiry guard the approval path. AI-created tasks carry provenance that excludes them from creation, due-date, and completion automation rules, including after backup restoration. These controls bound the integration's capabilities; they do not establish absolute security or reliable real-model behavior.
